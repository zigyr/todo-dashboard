# 方法论基线

> 目的：让产品由**行为机制**驱动，而不是功能清单。
> 适用：PRD、交互设计、复盘指标、后续迭代取舍。

## 1. 为什么需要方法论

效率工具失败，通常不是因为功能少，而是因为：

- 捕获很容易，澄清很难；
- 列表越来越长，行动越来越少；
- 工具换来换去，行为没有改变。

所以每加一个功能，都要回答：**它强化了哪个行为回路？** 回答不了，就不做。

## 2. 总回路：GTD

GTD（Getting Things Done）的五步是产品的骨架：

| GTD 步骤 | 在本产品中的实现 |
| --- | --- |
| Capture | 粘贴 URL，进入 inbox |
| Clarify | AI 提取 + 人工复核：这件事到底要做什么？ |
| Organize | 状态：next / doing / waiting / done / dropped |
| Reflect | 周复盘：做了什么、卡在哪、下周做什么 |
| Engage | 仪表盘的「现在做」+ 推荐排序 |

**保留**：next action、等待/放弃、周复盘、把模糊目标拆到可执行。

**舍弃**：复杂 context 列表、2 分钟法则的教条化、多层项目体系。v0 不为「完整性」牺牲启动速度。

## 3. 流动：Personal Kanban

Personal Kanban 的两条规则：

1. **可视化工作**：所有行动都在一个视图里，状态透明。
2. **限制 WIP**：同时进行的事越少，完成越快。

产品落点：

- `doing` 状态最多 3 条；超出时提示，而不是硬阻止。
- 记录 `started_at` / `done_at`，计算周期时间。
- 周复盘看「流动」：哪些卡住、卡了多久、为什么。

> 列表不是越多越好。看得见流动，才知道下一步。

## 4. 优先级：ICE / WSJF

### 4.1 为什么不用「AI 直接打分」

让模型直接给 0–100 分有三个问题：

- 不可复现：同一篇文章两次分析，分数可能不同；
- 不可解释：用户不知道为什么排第一；
- 不可调：无法按自己的偏好调整权重。

### 4.2 采用 ICE

- **Impact**：对当前目标的影响（1–5）
- **Confidence**：判断的信心（1–5）
- **Ease**：由预计耗时映射（1–5）

```text
ICE = Impact × Confidence × Ease
score = round(ICE / 125 × 100)
```

AI 只负责估算三个属性；排序由确定性公式计算。用户可以看到每个输入，也可以手动修改。

### 4.3 与 WSJF 的关系

WSJF（Weighted Shortest Job First）的本质是「延迟成本 / 工作规模」。本产品的 ICE 是它的轻量个人版：

- 延迟成本 ≈ Impact × Confidence
- 工作规模 ≈ Effort

对个人任务来说，ICE 更直观，也更容易解释。

### 4.4 防止「快速胜利成瘾」

纯按易度排序，会让人一直做 5 分钟的小事。对策：

- 默认按 ICE，而不是按耗时；
- 「由易到难」是显式切换，不是默认；
- 「现在做」可以被 pin，保留战略判断；
- 周复盘检查：这周做的事，是否服务于下周的重点。

## 5. 启动：Implementation Intentions

Gollwitzer 的研究指出：把意图写成「如果 X，那么做 Y」的具体计划，显著提高执行率。

产品落点：

- 每条行动必须有 `next_action`，且 ≤ 15 分钟；
- 复核时追问：**什么时候、在哪里、第一步是什么？**
- 仪表盘只突出一个行动，减少选择成本。

结合 Fogg 行为模型 `B = MAP`：

- **Motivation**：来源引文说明「为什么值得做」；
- **Ability**：下一步足够小，降低启动摩擦；
- **Prompt**：首页卡片、快捷键、周复盘提醒。

## 6. 反馈：AAR + 周复盘

After Action Review（AAR）的四个问题：

1. 原本预计发生什么？
2. 实际发生了什么？
3. 为什么有差异？
4. 下次怎么改？

周复盘议程（30 分钟）：

1. 清空 inbox（处理未复核的来源）；
2. 看本周 done / dropped；
3. 读放弃原因，找重复模式；
4. 选出下周 Top 3；
5. 为每一条写下下一步和时间。

产品落点：

- 放弃必须填原因；
- 周复盘生成 `review-YYYY-Www.md`；
- 指标看「周期时间、放弃原因、接受率」，而不是「任务总数」。

## 7. 从文章到行动：四级提炼

| 层级 | 问题 | 产出 | 是否进入仪表盘 |
| --- | --- | --- | --- |
| Quote | 文章说了什么？ | 精确引文 | 否 |
| Idea | 为什么重要？ | 关键观点 | 否 |
| Action | 应该改变什么？ | 行动 | 复核后进入 |
| Next action | 第一个物理动作是什么？ | ≤ 15 分钟 | 是 |

只有 Action 和 Next action 进入执行视图。Quote 和 Idea 用于追溯，不制造「又读了一遍」的错觉。

### 行动质量 rubric

1. 动词开头；
2. 有可验证的完成标准；
3. 有 ≤ 15 分钟的下一步；
4. 有原文引文，禁止编造；
5. 有耗时估算；
6. 不空泛（禁止「学习 X」「提升 Y」而没有下一步）。

## 8. 反模式

| 反模式 | 表现 | 对策 |
| --- | --- | --- |
| 任务坟场 | 只捕获，不澄清 | 未复核不进仪表盘 |
| AI 垃圾 | 自动接受所有提取 | 人工复核 + 质量 rubric |
| 虚荣指标 | 比谁的任务多 | 看完成率、周期、放弃原因 |
| 过度计划 | 花 2 小时整理系统 | 一个下一步，先做 15 分钟 |
| 工具跳跃 | 不断换新工具 | 方法论稳定，工具可替换 |
| 完美主义 | 等完美系统再开始 | v0 先跑通垂直切片 |

## 9. 对设计的直接约束

| 原则 | UI / 交互决策 |
| --- | --- |
| 一个下一步 | 首屏只突出 1 条，其余进列表 |
| WIP 限制 | doing 超过 3 条时提示 |
| 可解释排序 | 展示 I / C / E 与推荐分 |
| 执行意图 | 没有 next_action 不能进入 next |
| 反馈回路 | dropped 必填原因；周复盘生成文件 |
| 低摩擦 | 粘贴即导入；键盘可完成核心流程 |
