# 项目章程

> 状态：Draft v0.2 · 最后更新：2026-10-31

## 一句话

粘贴一篇博客，把它变成下一步行动。

## 背景

我看了很多优秀博主/UP 主关于工作效率、个人知识管理、独立开发的分享。可复现的方法很多，但真正困扰我的不是「不知道方法」，而是：

1. 信息过载，认知不足，不知道下一步该做什么；
2. 缺少鞭策与反馈，知道该做却启动不了；
3. 读到的内容停留在「收藏」，没有变成行动；
4. 普通 TODO 只记录任务，不解决「从哪开始」。

所以我想从「最感兴趣的那篇博客」开始，把「阅读 → 提炼 → 行动 → 复盘」做成一个自己每天真的会用的桌面工具。

## 问题定义

不是「任务太多」，而是**从「读到」到「做到」之间缺少一道工序**：把观点转成具体行动，并在执行后留下反馈。

## 目标用户

- v0：我自己。唯一用户、唯一开发者。
- v1（假设）：有相似困境的知识工作者、独立开发者、学生——读得多、做得少，缺少下一步。

## Jobs to be Done

- 当我读到一篇好文章，我想在几分钟内得到 3–7 个可执行动作，而不是收藏后再也不看。
- 当我打开仪表盘，我想知道「现在做哪一件」，而不是面对一长串列表。
- 当我完成或放弃一个行动，我想留下原因，供周末复盘。
- 当我一周结束，我想知道时间花在哪、哪些方法真的有效。

## 价值主张

从 reading 到 action 的最短路径。

## 范围

### v0 要做（待 PRD 确认）

- 粘贴博客 URL
- 抓取正文（readability）
- DeepSeek 分析并输出结构化行动
- 人工复核、编辑、取舍
- 仪表盘：一个「现在做」+ 推荐排序
- 完成/放弃记录
- 本地文件存储、CLI 导入、导出
- DeepSeek API Key 引导与安全存储
- 轻量周复盘

### v0 不做

- 手动任务录入（编辑 AI 提取结果除外）
- 日历、GitHub Issue、笔记集成
- 云同步、账号体系、协作
- 移动端
- 自动执行行动
- 多 LLM 供应商（v0 仅 DeepSeek）

## 设计原则

1. **URL in, action out**：输入是文章，输出是下一步。
2. **Human in the loop**：AI 只提议，不替用户做决定。
3. **File is the database**：数据是独立、可读、可迁移的文件。
4. **Local-first, BYOK**：本地优先，用户自带 API Key。
5. **Explainable ranking**：排序可解释，不是黑盒。
6. **One next action**：首页只回答「现在做什么」。

## 成功指标（假设，待验证）

- 从粘贴 URL 到看到第一个可执行行动 ≤ 60 秒
- 每篇文章产出 3–7 个行动，至少 1 个被接受
- 7 天后仍在使用
- 周复盘完成率 ≥ 80%
- 放弃行动有原因记录 ≥ 70%

## 风险

- LLM 产出空泛/错误的行动，制造「AI 垃圾任务」
- 博客抓取失败（JS 渲染、反爬、付费墙）
- 版权与隐私边界
- API 成本失控
- 范围蔓延成通用 TODO
- Windows SmartScreen / 代码签名

## 开放问题

- v0 是否只允许 URL 作为唯一捕获渠道？
- 是否允许编辑 AI 提取的行动？（建议允许）
- 是否在本地保存全文快照？
- `--source` 是导入副本，还是原地编辑外部文件？（建议副本）
- 技术栈：Tauri 还是 .NET/WPF？
- License：MIT 还是 Apache-2.0？
- 产品名是否继续用 Todo Dashboard？
